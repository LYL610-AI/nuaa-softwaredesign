## 1. 测试范围与主要内容

### 1.1 功能测试

#### 1.1.1 用户模块

| 测试项 | 测试内容 |
|--------|----------|
| 志愿者注册 | 填写手机号、密码、真实姓名、身份证号、性别、学历，验证注册成功；重复手机号/身份证号注册应提示失败 |
| 学校用户注册 | 填写手机号、密码、学校名称、负责人、许可证号、学校类型、地址，验证注册成功；重复许可证号注册应提示失败 |
| 三角色登录 | 志愿者/学校用户/管理员分别输入正确的手机号+密码，验证登录成功并返回正确 Token 和角色标识 |
| 错误登录 | 输入错误密码/不存在手机号，验证返回 "手机号或密码错误" |
| 获取用户信息 | 携带 Token 请求 `/api/user/info`，验证返回数据与注册信息一致 |
| 修改密码 | 输入正确原密码 + 新密码，验证修改成功；用新密码登录；用旧密码登录失败 |
| 修改个人信息 | 修改学历/性别/学校名称等字段，验证修改后数据正确 |
| 找回密码（志愿者） | 通过身份证号重置密码，验证新密码可登录 |
| 找回密码（学校） | 通过办学许可证号重置密码，验证新密码可登录 |
| 字段唯一性校验 | checkPhone / checkIdNumber / checkLicense 接口返回正确的 true/false |

#### 1.1.2 活动模块

| 测试项 | 测试内容 |
|--------|----------|
| 发布活动 | 学校用户填写标题、内容、招募人数、志愿时长、地址，验证发布成功（初始审核状态为待审核） |
| 活动列表 | 无需登录即可访问，验证返回数据含分页信息，默认按审核通过+发布时间排序 |
| 关键字搜索 | `?keyword=支教` 验证只返回标题包含"支教"的活动 |
| 状态筛选 | `?state=0` 验证只返回招募中活动；`?state=1` 只返回进行中；`?state=2` 只返回已结束 |
| 地区筛选 | `?region=南京` 验证只返回地址包含"南京"的活动 |
| 活动详情 | 验证返回完整的活动字段（标题、内容、人数、时长、地址、封面图 pictureUrl、开始/结束日期、状态等） |
| 审核活动 | 管理员审核通过（auditState=1），验证活动状态更新、审核时间记录；管理员退回（auditState=2） |
| 修改活动 | 发布者修改标题/内容/图片/日期等字段，验证修改成功 |
| 活动封面图 | 发布/修改活动时传入 pictureUrl（通过文件上传接口获取），验证详情中正确展示 |
| 活动状态流转 | 招募中(0) → 进行中(1) → 已结束(2) 各状态切换正常 |
| 删除活动 | 发布者或管理员可删除活动 |
| 我的活动列表 | 学校用户查看自己发布的活动，验证仅返回自己的活动 |
| 提交活动总结 | 填写总结标题和内容，验证提交成功 |
| 审核活动总结 | 管理员审核通过/退回总结 |
| 已审核活动列表 | `/api/activity/reviewed` 验证只返回 auditState=1 的活动 |
| 已审核总结列表 | `/api/activity/summary/reviewed` 验证只返回已审核通过的总结 |

#### 1.1.6 权限与认证

| 测试项 | 测试内容 |
|--------|----------|

## 2. 测试方法

### 2.1 黑盒测试（主要方法）

- **等价类划分**：针对输入字段（手机号、身份证号、密码长度、分页参数等）划分有效和无效等价类
- **边界值分析**：分页边界（page=0、page=1、page=2147483647）、招募人数边界（0、1、极大值）
- **场景法**：设计典型业务流程测试用例——注册→登录→浏览活动→报名→审核→参与活动→发帖评论
- **错误推测法**：基于经验推测可能出错的环节——重复注册、重复报名、越权操作、Token 过期等

### 2.2 白盒测试（辅助方法）

- 对关键业务逻辑（审核状态流转、权限判断、JWT 解析）阅读源码，设计覆盖所有分支的用例
- 对 DAO 层 SQL 进行直接测试，确保多表 JOIN 查询结果正确

### 2.3 测试工具

- **Postman / Apifox**：手动测试所有 API 接口，验证请求参数和响应格式
- **JUnit**（可选）：编写后端单元测试覆盖 Service 层核心逻辑

## 4. 测试完成准则

本项目为非严格系统（课程设计/教学项目），采用"基于测试用例"的准则：

1. **功能性测试用例通过率达到 100%**：所有接口的正向流程和异常流程测试用例全部通过
2. **非功能性测试用例通过率达到 95%**：性能、安全性、界面测试用例通过率不低于 95%
3. **高优先级缺陷全部关闭**：所有阻塞核心流程的 Bug 必须修复并回归通过
4. **四重审核流程全链路通过**：活动审核、报名审核、帖子审核、总结审核的完整流转全部正确
